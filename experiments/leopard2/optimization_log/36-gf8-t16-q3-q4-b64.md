# 36 — GF8 T=16 Q3/Q4 fused B64 encoder

## Hypothesis

For legacy-high GF8 with `R=9..16`, the mature encoder inverse-transforms each
16-shard message block into memory, XORs it into a 16-shard accumulator, then
reloads that accumulator for the parity transform.  At 64-byte shards this
traffic and the generic pointer schedule dominate the arithmetic once the
message spans three or four blocks (`K=33..64`).  The already-qualified Q2
generated circuit suggested that merging the final inverse layer, XOR, and
first forward layer would make the paper's redundancy-side algorithm win here
too.

## Implementation

The AVX2-only packed terminal now covers `K=33..65`, `R=9..16`, and exactly
64-byte shards.  It retains the legacy-high wire profile:

- `T=16`, `N=128`, `D=112`;
- parity coordinates `0..R-1`;
- application message coordinates `16..16+K-1`;
- shortened zero message coordinates `16+K..127`.

For `K=33..64`, a generated Q3/Q4 circuit evaluates the same shifted block
IFFTs as Leopard1, but keeps one 16-row primary accumulator and one 16-row
secondary block.  It fuses each block's outer inverse layer into the XOR and
fuses the last such XOR with the first parity FFT layer.  The public scratch
contract remains 32 shard rows; no new API or wire identifier is introduced.

`K=65` has the same `[128,112]` parent.  Its extra source is coordinate 80.
The generated Q4 result is therefore updated by that source's exact Lagrange
column.  In legacy GF8 log representation, the parity-row multipliers are:

    124, 248, 72, 227, 143, 199, 62, 132,
    33, 36, 31, 144, 66, 18, 9, 241

The generated entry is isolated in a trailing ELF section.  This preserves the
previously qualified Q2 circuit and the mature T32/T64 hot-code page addresses;
earlier in-TU/page-aligned variants moved unrelated text and were rejected.

## Correctness and safety

The focused suites compare every `K=33..65` at `R=16`, plus the `R=9`
boundary, with the independent direct systematic oracle.  A dedicated
`K=65,R=9` basis case zeros sources 0..63, makes source 64 nonzero, and checks
all parity rows against both the direct oracle and Leopard1; parity row 8 locks
the single-output tail case that caught an earlier callback-contract bug.

Tests also cover representative random Leopard1 parity at Q3/Q4 boundaries,
unaligned packed slabs, guard bytes, exact/short/misaligned scratch, one-item
batch, packed input/output overlap, scratch-data and scratch-metadata overlap,
and sparse/detached fallbacks.  The feature-disabled build retains the mature
path and excludes `K=65` from the terminal.  Binary inspection found AVX2 VEX
instructions only, no EVEX/ZMM/opmask instructions, no vector spills, and
bounded reads and writes for all input, output, and scratch rows.

The final diagnostic matrix also sweeps every `K=33..64` at both the T32/R32
and T64/R33 boundary, tests representative FORCE_TRANSFORM fallback, and
checks AUTO/scalar/SSSE3 backend exclusion.  Release qualification passed 7/7
focused tests, strict Clang 18 passed, the feature-disabled build passed, and
Clang 18 ASan+UBSan+LSan passed the expanded diagnostic suite in 305.12
seconds with 71,680 KiB peak RSS and no swap.  The separately linked
production-archive sanitizer test passed in 73.37 seconds.

The frozen candidate is SHA-256
`eb1791fd2e14deb99a9fa5199d36edf6eb533a6d21d81f53ef95b3377262e689`.
The predecessor is
`971db192862dc61beb3375bf6c1ad0d729abb5a6a245f3b271a003ed187ab60c`.

The last row exercises the adjacent T64 route: candidate/predecessor is
1.0019x [0.9893, 1.0145].  Every predeclared inactive predecessor comparison
has a lower confidence bound above 0.98, including K32/R16, K66/R16,
K62/R8, K62/R17, K62/R33, and K65/R65.

The broad runner's overall flag is false only because it also asks this scoped
candidate to repair pre-existing, unrelated exact-Leopard1 deficits at
K62/R8, K66/R16, and K65/R65.  Those cells are not promoted by this change and
remain separate regression work; their failure is not counted as evidence for
or against the T16 terminal.

## Result

Landed for the exact GF8/AVX2 B64 region above.  It reproduces legacy parity,
delivers the redundancy-side structural win predicted by the LCH algorithm,
and leaves inactive code-layout controls within the predeclared 2% budget.
The next largest measured GF8 encode deficit is K62/R8/B64, followed by
K66/R16/B64.
